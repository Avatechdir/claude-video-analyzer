# DESIGN — нормализация транскрипта (класс A) + пунктуация (класс C)

Статус: дизайн (готов к реализации). Контекст: скилл `video-analyzer` + Transcript Editor.
Связано: `DESIGN_frame_selection.md`, шаг 7c в `SKILL.md`, `scripts/words_apply.py`.

## 0. Принципы (из brainstorm)

- **Три класса правок речи, разной природы:** A — механика (детерминированно), B — ослышки
  (модель, уже есть), C — пунктуация по смыслу (модель).
- **Исходники Whisper НЕ мутируем.** `audio.words.json` — источник истины, id стабильны.
  Все правки — НАЛОЖЕНИЯ в `edits.json` (как ручная склейка в редакторе). Отсюда: миграции нет,
  работает ретроактивно, редактор дорабатывать не нужно.
- **Что суждение — подсвечиваем (B, C); что механика — тоже наложение, но помечено `derived:merge`**
  (лёгкое подчёркивание «Слито из…», пользователь согласовал).
- **Порядок A → B → C.**

## 1. Детерминированный компонент `scripts/normalize_transcript.py`

Одна логика склейки, два выхода.

### 1a. Правило склейки дефиса (ядро)
Токен `w` сливается с ПРЕДЫДУЩИМ видимым словом, если `w.word.strip()` матчит **`^-\p{L}`**
(дефис + БУКВА). Результат: `out = prev.strip() + w.strip()` (пробел перед дефисом уходит).
Примеры: `что`+`-то?`→`что-то?`, `во`+`-вторых,`→`во-вторых,`, `по`+`-моему.`→`по-моему.`

**Исключения (НЕ сливать):**
- дефис + цифра (`^-\d`) — отсекает галлюцинацию «-4-4-4…» (§60) и подобный мусор;
- одиночный `-`/`—` или `- слово` (дефис-разделитель с пробелом после) — это тире между
  клаузами, не клитика; матч `^-\p{L}` его не ловит по построению;
- если предыдущий токен кончается на `.?!…` (граница предложения) — не клеим через границу.

Таймкод объединённого: `t0 = prev.start`, `t1 = w.end` (диапазон пары; для суффикса корректно).
Множественные подряд дефис-токены сливаются в цепочку слева направо (survivor = самый левый).

### 1b. Выход «эмиттер merge-правок» (для редактора)
`normalize_transcript.py --emit-merges <project_dir>` → печатает карту правок для `edits.json`:
```json
{"19": {"out": ["что-то?"], "span_to": 20, "kind": "norm"},
 "20": {"out": [], "into": 19}}
```
Формат ровно как у ручного merge в `main.py:merge_words` (survivor `{out, span_to}` + поглощённые
`{out:[], into:survivor}`), плюс наше поле `kind:"norm"` (см. §2). Применяется тем же
`words_apply.py` (нужно доучить его понимать merge-записи — см. §2b).

### 1c. Выход «плоский текст» (для отчёта/transcript.md)
`normalize_transcript.py --text <audio.srt|txt>` → нормализованная строка: склейка дефисов +
схлопывание кратных пробелов + удаление пробела перед `,.?!`. Это чистый текст, который модель
читает при написании отчёта (см. §3). Работает на строке, не на словах.

## 2. Класс C (пунктуация) и различение B/C в `edits.json`

- Схема `edits.words[id]` терпит лишние поля: `merge.py`/`main.py` читают только known-ключи через
  `.get()`, неизвестные игнорируют и сохраняют при round-trip. → безопасно добавить **`kind`**:
  - `kind:"norm"` — механическая склейка (A);
  - `kind:"punct"` — пунктуация по смыслу (C);
  - B (ослышки) — без `kind` (или `kind:"hear"`), как сейчас.
- **Без обязательной доработки фронта:** C рендерится как обычная подсвеченная правка (замена
  токена с иной конечной пунктуацией, напр. `получаем`→`получаем,`). `kind` — провенанс на будущее
  (позже фронт сможет красить пунктуацию иначе). Требование «без доработки фронта» соблюдено.
- Класс C генерирует **модель** (как B): читает нормализованный текст, предлагает правки-запятые
  1:1 на уровне токена (меняется только конечная пунктуация слова), пишет в `edits.json` с
  `kind:"punct"`.

### 2b. Доработка `words_apply.py`
Сейчас применяет только замены `{out:[tok]}`. Добавить:
- приём merge-записей (`{out, span_to}` + `{into}`) из `--emit-merges`;
- **защита от коллизий:** если у survivor ИЛИ у любого поглощаемого id уже есть правка
  (пользователя/B) — склейку ПРОПУСТИТЬ и залогировать (не перетирать ручную работу);
- `kind` пробрасывать как есть.

## 3. Консистентность отчёта

Отчёт НЕ мутирует исходники. Модель при написании `report.md` читает **нормализованный плоский
текст** (`normalize_transcript.py --text audio.srt`), а не сырой. Так отчёт и редактор дают
одинаково чистый текст, но каждый своим путём (отчёт — из плоского нормализованного; редактор —
из слов + наложения). Сырые `audio.*` остаются нетронуты (они и есть провенанс, отдельный `.raw`
не нужен, раз источник не переписываем).

## 6. Риски / край

- «чего-чуть» (склеили верно по пробелу, но само слово — ослышка) — A чинит ТОЛЬКО пробел, слово
  остаётся на B/пользователя. Ок.
- «слово - слово» (тире-разделитель) — не ловим (нет `^-\p{L}`). Ок.
- Цифровой мусор «-4-4» — отсечён `^-\d`. Ок.
- Пунктуация (C) может перестараться — потому подсвечена и откатываема.
