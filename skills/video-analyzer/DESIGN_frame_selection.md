# Дизайн: content-aware отбор кадров (ценность + разнообразие)

## Проблема
На демо с быстрым монтажом в отчёт попадало ~10% полезных экранов вместо ожидаемых ~80%.
Две причины:
1. **Кадры на смазанных переходах** — `plan_frames.awk` брал кадр в момент смены сцены
   (середина whip-pan) → смаз. **[ИСПРАВЛЕНО]** midpoint-по-отрезку между склейками.
2. **Отбор в бюджет слеп к содержимому** — резали по длине отрезка/равномерно по времени;
   это прокси, не про суть. Нужен отбор по ЦЕННОСТИ (полезный UI) и РАЗНООБРАЗИЮ (не дубли).

## Ключевой принцип: кто что судит
- **Тайминг-планировщик (`plan_frames.awk`, до извлечения)** — слеп к пикселям. Только режет
  переходы (MIN_SEG) и даёт midpoint каждого показа. НЕ судит ценность.
- **Скрипт-дедуп (CPU, 0 токенов)** — перцептив-хэш, схлопывает near-identical. Механика.
- **Субагент-скринер (зрение, по ТАМБНЕЙЛАМ)** — судит ЦЕННОСТЬ и РАЗНООБРАЗИЕ, отбирает в бюджет.
- **Основная модель (я, шаг 6, ПОЛНОЕ разрешение финалистов)** — настоящий анализ + подписи.
- Никакой отдельной «модели для кадров»: только интеллект, уже доступный в харнессе
  (я + субагенты). Ни внешнего API, ни локальной VLM — скилл принципиально локальный и лёгкий.

## Токен-экономия (главный приоритет)
Токены тратит ТОЛЬКО чтение картинок моделью. Всё остальное — CPU. Поэтому:
- pHash-дедуп (CPU) режет набор до чтения.
- Скринер смотрит **контактные листы** (montage из ~30 пронумерованных тамбнейлов = ОДНА
  картинка вместо 30) → кратно меньше токенов, и дубли видны бок о бок (отбор точнее).
- Полное разрешение читаются ТОЛЬКО финалисты (≤ бюджет), один раз, основной моделью.

## Конвейер
```
1. extract.sh (щедро)          — midpoint-по-отрезку. CPU. [midpoint уже сделан]
2. pHash-дедуп (новый, CPU)    — схлопнуть near-identical (мягкий порог, только уверенные дубли)
3. контактные листы (ffmpeg)   — montage по ~30 тамбнейлов/лист, с номерами
4. субагент-скринер            — читает лист(ы), отдаёт keep-list:
                                 {индекс, категория (UI/зал/голова/переход), ценность, дубль-группа}
                                 режет уверенные дубли/смаз/голову; при сомнении — ОСТАВЛЯЕТ (перекос в охват)
5. [если survivors > бюджета]  — второй контактный лист из survivors → финальный отбор в MAX_FRAMES
6. осн. модель (шаг 6)         — Read финалистов в ПОЛНОМ разрешении → frames_context + отчёт
7. кросс-чек с транскриптом    — модуль есть в речи, а экрана нет → догнать фокусом (правило в SKILL.md)
```

## Масштабирование (много кадров)
- Число листов = (после pHash) / 30, а НЕ (сырые)/30 — дедуп сначала сильно сокращает.
- Иерархия при большом числе листов: per-лист top-K → собрать survivors →
  (если > бюджета) второй лист из survivors → финальный отбор. Кросс-лист дедуп работает,
  стоимость ограничена.
- **Бюджет vs охват:** если уникальных ценных экранов больше бюджета — 80% недостижимо по
  определению (оставим самые ценные). Значит `MAX_FRAMES` надо поднимать под насыщенные демо
  (дёшево — CPU; дорого только чтение, а его гейтит скринер). Возможно: дефолт MAX_FRAMES выше
  для демо-жанра, либо адаптивно от числа смен сцены.

## Тамбнейлы: разрешение
- Для ОТБОРА хватает макета/структуры → тамбнейл ~384–512px по ширине (различает типы экранов,
  ловит смаз/дубли). Тонкие текстовые различия (две карточки блюд) дораз­решаются на ПОЛНОМ
  разрешении у осн. модели → поэтому скринер при сомнении оставляет, не режет.

## Что реализовать — СДЕЛАНО
- [x] `plan_frames.awk` — midpoint-по-отрезку + `MIN_SEG` (переходы) + равномерный запасной отбор.
- [x] `dedup_frames.py` — pHash-дедуп (PIL 16x16 gray, mean-abs-diff, порог `DEDUP_THRESH`) → `_kept.tsv`.
- [x] `contact_sheets.py` — контактные листы (PIL montage, номера+таймкоды Arial) → `_sheet_NN.png` + `_sheet_index.tsv`.
- [x] `extract.sh` — `EXTRACT_MAX` (щедрое извлечение, 300) отдельно от `MAX_FRAMES` (финальный бюджет).
- [x] SKILL.md — шаг 5b (дедуп → листы → субагент-скринер с промптом + схемой keep-list) → 5c скаффолд →
      6 чтение ФИНАЛИСТОВ в полном разрешении; правило охвата ≥80% + догон фокусом при пропуске.
